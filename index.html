GitHub-Verbindung

prices.csv / transactions.csv / stammdaten.csv leben im Repo, nicht im Browser
Personal Access Token mit Contents: Read and write auf dieses Repo (Fine-grained PAT unter github.com → Settings → Developer settings → Personal access tokens).
Pfade im Repo: data/prices.csv, data/transactions.csv, data/stammdaten.csv — werden beim ersten Speichern automatisch angelegt.
Bei aktivierter Checkbox liegt das Token im localStorage dieses Browsers (unverschlüsselt) und wird beim nächsten Öffnen automatisch wieder eingefüllt. Nur auf einem eigenen, vertrauenswürdigen Gerät aktivieren — nicht auf gemeinsam genutzten Geräten. Ohne Häkchen bleibt alles nur im Speicher dieser Session, wie bisher.

Neue Splint-Exporte hochladen

Die beiden Original-Exportdateien von Splint
AInvestment Opportunities Export
Aktuelle Positionen mit heutigem Kurs. Wird als ein Kurspunkt pro Monat in prices.csv übernommen (letzter Upload pro Monat überschreibt vorherigen).
BActivities Export
Vollständiges Transaktionsprotokoll von Splint. Neue Transaktions-IDs werden ergänzt, bestehende nicht dupliziert.
Reihenfolge pro Session: zuerst oben «Von GitHub laden», danach A und B hochladen. Ist eine GitHub-Verbindung (Owner/Repo/Token) gesetzt, werden prices.csv, transactions.csv und stammdaten.csv nach jedem Upload automatisch im Repo aktualisiert — «Auf GitHub speichern» ist dann nur noch nötig, nachdem im Tab «Wertschriften» Name, Kategorie, Subkategorie oder Notizen geändert wurden.

Manueller Import / Export (Fallback ohne Token)

Nur nötig, falls keine GitHub-Verbindung genutzt wird
prices.csv laden
transactions.csv laden
Stammdaten (Name, Kategorie, Subkategorie, Notizen) gibt es nur als Export/GitHub-Stand — kein manueller Upload, da es dafür keine externe Quelldatei gibt. Bearbeitung erfolgt direkt im Tab «Wertschriften».
